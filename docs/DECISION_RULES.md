# MissionCompiler V0.1 决策规则

本规则集把模型理解与不可绕过的政策分开。模型生成归一化事实，规则引擎只对事实做确定性计算。实现见 `src/missioncompiler/decision_engine.py`。

## 1. 决策优先级

发生冲突时按以下顺序处理：

1. 用户明确禁止项。
2. 红色外部动作和供应链信任门。
3. 当前环境事实与管理员要求。
4. 验收标准和回滚条件。
5. 成本、速度和便利性。

模型置信度不能覆盖前四项。

## 2. 归一化输入

规则引擎使用以下事实：

- 任务类型与需求清晰度。
- 预计文件数与模块数。
- 是否修改文件、是否为 Git 仓库、工作区是否有未提交改动。
- 是否访问网络、安装能力或进行视觉检查。
- 是否难以回滚。
- 风险标签与外部动作。
- 是否违反用户约束。
- 能力来源是否可信。

自然语言关键词不能直接触发政策。事实必须来自仓库、配置、工具状态、可信外部来源或用户明确陈述。

## 3. 风险等级

### 绿色

同时满足：

- 不修改文件。
- 不访问网络。
- 不安装能力。
- 不执行外部动作。
- 不包含红色风险标签。

示例：读取源码、解释代码、搜索位置、分析本地日志。

### 黄色

不属于红色，但至少包含：

- 修改 workspace。
- 限定网络读取。
- 安装可信且固定版本的能力。
- 低风险外部读取。

黄色操作在执行方案卡中一次批准。

### 红色

包含以下任一风险标签：认证、数据库迁移、付款、生产、监管、秘密、安全敏感、交易、破坏性、个人数据；或包含以下外部动作：删除远端数据、生产部署、修改生产数据、付款、发布、真实订单、监管提交、发送消息。

红色动作在发生前逐次批准。一般“按方案执行”不能替代逐次批准。

## 4. 阻塞条件

以下情况直接 `blocked`：

- 方案与用户明确约束冲突。
- 所需 Skill、插件或 MCP 的来源、版本或权限无法建立信任。

阻塞不是一种可被普通确认绕过的审批状态。必须更改方案、补足证据或选择可信替代项。

## 5. Plan / Direct 评分

| 条件 | 分数 |
|---|---:|
| 预计修改至少 4 个文件 | +2 |
| 跨至少 2 个模块 | +2 |
| 需求部分清晰 | +2 |
| 需求不清晰 | +4 |
| 需要网络 | +1 |
| 需要安装能力 | +2 |
| 需要视觉检查 | +1 |
| 难以回滚 | +3 |
| 有未提交改动且要修改文件 | +1 |
| 小功能 | +1 |
| 项目安装或配置 | +2 |
| 存在外部动作 | +3 |
| 存在高风险标签 | +4 |

满足任一条件时使用 Plan：

- 总分至少 4。
- 存在认证、数据库迁移、付款、生产、监管、秘密、安全敏感或交易标签。

其余使用 Direct。Direct 仍然可以有审批、测试和 Review。

## 6. 模型与推理层级

规则只输出层级，不输出具体模型名：

- `strong + high`：高风险、总分至少 7，或需求不清晰。
- `balanced + medium`：会修改文件、总分至少 3，或需要网络。
- `fast + low`：其余简单只读任务。

运行时必须从真实模型目录解析层级。若推荐层级不可用，选择同层可用模型；若不存在，降级前向用户解释影响，不静默替换。

## 7. 工作区策略

| 条件 | 策略 |
|---|---|
| 无文件修改、无外部动作 | `read_only` |
| 仅有外部动作 | `external_only` |
| 非 Git 项目且要修改 | `snapshot_workspace` |
| Git 项目，Plan / 脏工作区 / 多文件修改 | `isolated_worktree` |
| Git 项目，干净且单文件 Direct 修改 | `current_workspace` |

不得把用户未提交改动复制、覆盖或清理为“准备工作”。

## 8. Reviewer

以下任一条件启用 Reviewer：

- 修改文件。
- 安装 Skill、插件或 MCP。
- 风险等级为红色。

Reviewer 检查 TaskSpec 的验收条件、禁止项和变更范围，不只看代码风格。

## 9. 能力选择

按以下顺序解析：

```text
当前可用且可信
→ 已安装但未启用
→ 官方或可信目录中的固定版本
→ 用户/团队私有批准能力
→ 当前任务内临时方法
→ 不增加能力执行
```

只有满足以下全部条件才建议安装：

- 没有现有能力可完成。
- 能显著提高成功率或提供必需外部访问。
- 来源、版本、权限和卸载方式可说明。
- 用户批准安装范围。

未知来源的 MCP 默认阻塞。插件安装在正式客户端中不能依赖仍标记为 under development 的 App Server 接口。

## 10. 完成与停止

完成必须同时满足：

- 所有 required 验收项通过。
- 测试、构建、静态检查或视觉检查按 TaskSpec 执行。
- Reviewer 未发现阻断问题。
- 没有越过批准范围。
- 最终报告包含修改、证据、剩余风险和回滚方式。

遇到以下任一情况停止并重新编译：

- 关键事实无法验证。
- 所需权限、文件或外部动作超出批准范围。
- 有界修复循环后验证仍失败。
- 红色动作没有即时批准。
- 用户约束与实现路径冲突。
