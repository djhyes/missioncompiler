# TaskSpec V0.1

TaskSpec 是 MissionCompiler 的结构化执行合同。它不是把原始提示词扩写成长提示词，而是把目标、环境事实、风险、能力、权限、验收和回滚放进同一个可验证对象。

机器可读定义见 `schemas/task-spec.schema.json`。

## 编译边界

```text
原始需求
  ↓ 只读环境扫描＋意图理解
归一化事实 facts
  ↓ 确定性策略
recommendation＋approvals
  ↓ 用户批准
受约束执行＋验证＋回滚
```

模型负责：

- 理解自然语言目标。
- 从仓库、配置和工具状态中提取事实。
- 形成交付物和可验证验收标准。
- 根据语义匹配候选 Skills、插件和 MCP。

确定性策略负责：

- 风险等级。
- Plan / Direct。
- 模型层级与推理强度。
- 当前工作区、worktree 或快照工作区。
- 审批时机。
- 高风险硬限制和停止条件。

## 关键字段

| 字段 | 含义 | 规则 |
|---|---|---|
| `source.raw_prompt` | 用户原始需求 | 原样保留，不偷偷改写意图 |
| `intent` | 目标、交付物、不变量和验收条件 | 每个验收条件必须写明验证方法 |
| `environment` | 当次只读扫描快照 | 不把旧缓存伪装成当前事实 |
| `facts` | 供确定性策略使用的归一化事实 | 只能来自可追溯观察或明确用户约束 |
| `recommendation` | 执行路由 | 模型用“层级”表示，真实模型运行时解析 |
| `approvals` | 审批合同 | 红色动作必须逐次批准 |
| `verification` | 完成证据 | Agent 自述不能代替检查结果 |
| `rollback` | 撤销方式 | 修改前就必须存在 |

## 模型层级

TaskSpec 不写死具体模型：

- `fast`：只读查找、分类、低不确定性任务。
- `balanced`：普通代码修改和测试修复。
- `strong`：复杂计划、强不确定性或高风险任务。

正式 App 应从 Codex App Server 的 `model/list` 读取用户当前可用模型、默认值和支持的 reasoning effort，再把层级解析为真实选择。

## 能力状态

每个能力都必须包含用途、状态、来源和权限：

- `available`：当前会话可直接使用。
- `installed`：本机已安装但可能未加载。
- `missing`：确有必要但未安装。
- `untrusted`：来源、版本或权限无法建立信任；不得安装。
- `not_needed`：候选能力与任务无关。

缺少能力不代表一定要安装。优先顺序是：已有能力、可信已安装能力、可信目录候选、临时任务内方法、无额外能力执行。只有能力能显著改变成功率且无法由现有工具完成时，才建议安装。

## 审批语义

- `none`：只读、本地、无外部副作用。
- `upfront`：工作区写入、限定网络访问、可信能力安装等黄色操作；执行方案卡一次批准。
- `per_action`：发送、发布、生产、付款、真实订单、监管提交等红色动作；发生前逐次批准。
- `blocked`：违反用户约束、来源不可信或无法建立安全边界；不能用一般批准绕过。

批准只覆盖卡片中列出的路径、权限、能力和动作。执行中发现范围扩大时，旧批准失效，必须重新编译方案。
